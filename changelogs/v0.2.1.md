# Changelog

## [0.2.1] - 2026-09-26

This release improves evaluation budget accounting when adapters run metrics more than once per example.

**Optimization engine and strategies:**

* The engine now tracks the actual number of metric calls reported by evaluators instead of assuming one call per validation example.
* Seed-candidate initialization charges the reported metric-call count, so repeated executions during the initial valset evaluation count correctly toward `max_metric_calls`.
* Evaluation caching propagates reported call counts for uncached batches, keeping budget usage accurate across the run.

**API surface (`optimize`, callbacks, results):**

* Evaluator functions may return a fourth value with the number of metric calls for the batch; omitting it still defaults to one call per example for backward compatibility.
* Adapters can set `num_metric_calls` on `EvaluationBatch` to report repeated executions; `reported_metric_calls()` derives the charge from that value or the batch size.
